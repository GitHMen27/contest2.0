# Evals для RAG по регламентам

Набор из 50 размеченных вопросов (`dataset.json`) и скрипт `run_evals.py`, который измеряет, насколько хорошо работает поиск и весь цикл «вопрос → ответ со ссылками».

## Что внутри набора

| Категория | Вопросов | Что проверяет |
|---|---|---|
| factual | 17 | вопрос близок к тексту регламента |
| numeric | 16 | нужна точная цифра («90%», «45 минут») |
| colloquial / paraphrase | 7 | вопрос сформулирован разговорно или другими словами |
| out_of_scope | 5 | ответа в регламентах нет совсем: нужен отказ |
| near_miss | 4 | тема рядом (зарплата, скорость на трассе), но ответа нет: самая трудная проверка на выдумывание |
| injection | 1 | попытка заставить модель игнорировать инструкции |

У вопросов с ответом указаны документ и раздел, где ответ лежит (`expected`), и факты, которые должны быть в тексте ответа (`must_contain`: внутри группы достаточно любого варианта, групп должны совпасть все).

## Запуск

Из папки `ai-service/`, с активированным `.venv` и заполненной базой:

```powershell
python ..\evals\run_evals.py retrieval                         # только поиск (быстро, чат-модель не нужна)
python ..\evals\run_evals.py retrieval --compare-instruction   # с инструкцией для вопросов и без неё
python ..\evals\run_evals.py answer                            # полный цикл, как /rag/ask
python ..\evals\run_evals.py all
```

Параметры: `--only q01 q07`, `--category numeric`, `--limit 5`, `--pause 1.5` (если упираетесь в лимиты), `--fail-under 0.9` (код выхода 1 при метрике ниже порога). Отчёты сохраняются в `evals/results/` (в git не попадают).

## Метрики

Поиск: в первых 4 результатах (столько показывает приложение) есть нужный документ (`doc_hit@4`) или нужный раздел (`section_hit@4`), MRR.
Ответы: доля верных ответов, ложные отказы, ссылки `[1]`, `[2]` на реальные источники, верные отказы (нет ответа → отказ без источников).

## Как расширять набор

Добавь в `dataset.json` вопрос с новым `id`. Тест `python -m pytest -q` проверит, что документы и разделы в `expected` существуют в `ai-service/docs-corpus/`. Лучшие новые вопросы это те, на которых система реально ошибалась на демо.
